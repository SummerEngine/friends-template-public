# Friends template: notes for coding agents

This is a template: a finished online party game for 2 to 10 players, made with Summer Engine (a Godot 4 fork), for people to build
their own game from. Everything in it is open to change: modes, levels, mechanics, characters, menus, the look, the sound. Build what
the person asks for. Use the "how much work" table in `README.md` to plan: small changes go straight in; for a bigger one (a new mode,
a new shared physics object, a different camera or genre) say briefly how you will approach it, then do it.

Start with `README.md` ("Start here": the games, how hard each kind of change is, where to look), then the docs it points to.

## First run

When someone asks for a game from this template:

1. **Set up.** If Summer is not connected yet, run `npx -y summer-engine@latest setup <your agent> --yes`
   (https://docs.summerengine.com/quickstarts/coding-agent). Clone the repo, import it once (`$S --headless --import --path demo`)
   and run it so you know it plays.
2. **Ask what they want to make.** Show the starting points in a sentence each: **The Show** (race, survive, crown; 2-10 players),
   **Glass carry** (two players carry something fragile), **Balloon** (3-10 players keep a balloon up), or one of the **minigames**.
   Ask which one is closest to their idea and what they would change: theme, name, characters, mechanics, levels.
3. **Plan, then build.** Set `"mode"` in `demo/cast/cast.json` to their pick, then work through their changes with the "how much
   work" table in the README in mind. Play it after each step, and run the checks below before you call it done.

## The games in this project

The cast's `"mode"` (`demo/cast/cast.json`) picks which game the lobby offers. Every mode stays in the repo.

| `mode` | Players | What it is | Notes |
|---|---|---|---|
| `show` (the default) | 2-10 | Three rounds: a race, a falling-floor survival, a climb to the crown. Four or more: elimination; two or three: points. | `docs/party-show.md`, `docs/swappables.md`, `docs/items.md` |
| `carry` | 2-10 | Two players carry the painting (or `"object": {"kind": "glass"}` for a glass pane) through levels; three to ten keep a balloon up instead. `run`: `time_attack` or `endless`. | `docs/painting-api.md`, `docs/level-format.md` |
| `who_said_it` | 2-10 | A catchphrase shows; everyone runs to whoever says it | `docs/modes/who_said_it.md` |
| `friend_swap` | 3-10 | Everyone plays as someone else, then guesses who is who | `docs/modes/friend_swap.md` |
| `hot_potato` | 2-10 | Pass the thing on before it pops | `docs/modes/hot_potato.md` |
| `shove_off` | 2-10 | Shove each other off a shrinking floor | `docs/modes/shove_off.md` |

How a mode is built (rules on the server, a view on each player, its HUD) and how to add one: `docs/modes.md`.

## Easy wins: the cast

Most "make it ours" changes need only `demo/cast/cast.json` and the files with fixed names next to it (logo, pictures, voice clips,
banners, a hero prop). Every field, its size and its fallback: `docs/slots.md`; what the show lets you swap: `docs/swappables.md`.
A missing or bad field falls back to the template on its own. Two full examples: `cp -R samples/tidewheat/. demo/cast/` (a bakery)
and `cp -R samples/acme/. demo/cast/` (couriers). Pictures: PNG, JPEG or WebP, at least 256 px on the short side, under 4 MB.

## Before you change code

- **Online play is the same code on every machine.** `demo/game/game_run.gd` runs in three roles: local (one keyboard), authority (the
  server) and replica (each online player). Gameplay rules belong on the authority side (`demo/network/match_controller.gd`,
  `demo/modes/<id>/rules.gd`); what players only see belongs in views (`demo/modes/<id>/view.gd`, `demo/client/`). A change that works on one
  keyboard can still break online, so check both (`docs/core-shell.md`).
- **Levels** are data: `demo/levels/level_NN.json` (`docs/level-format.md`). Prefer a new level file over code.
- `demo/network/composition.tres`, `demo/client/main.tscn` and `demo/authority/main.tscn` are generated by `tools/build_network.gd`
  (run by the staging tools); regenerate them rather than hand-editing.

## Wiring multiplayer

The game is online multiplayer already; keep it that way as you build. `docs/multiplayer.md` maps this project onto Summer's model
(which file is the authority, owner-written and authority-written State, Commands) and says how much work each kind of change is.
For the how-to, load the Summer `multiplayer` skill (then `multiplayer-state`, `multiplayer-movement`, `multiplayer-testing`) through
the Summer MCP, or read https://docs.summerengine.com/build/multiplayer. Test with one keyboard first, then with Local Play.

## Checks to run

- `python3 tools/cast_check.py`: the cast is valid (fields, sizes, files). There is no file lock in this template.
- `python3 tools/level_lint.py demo/levels`: every level file is well formed.
- `python3 -m unittest discover -s tools -p 'test_*.py'`: the tools' unit tests.
- `python3 tools/ship.py`: cast check, clean scan, in-engine check and a Web export in one go; its last line is `SHIP ok=... link=...`.
- Then **play it**. Two players on one keyboard: `$S --path demo`; online with a hosted build: `SUMMER_BIN=$S tools/stage_hosted_export.sh <label>`
  and upload it on Summer Games (`docs/build-tooling.md`). With the Summer MCP connected you can also run and screenshot the game from the agent.

The engine binary is `$SUMMER` or `$S` (macOS default `/Applications/Summer.app/Contents/MacOS/Summer`; pass the path on Windows and Linux).
Import once with `$S --headless --import --path demo`.

## Content

Games made from this template are public. Use art, sound and code you have the rights to and credit what you didn't make
(`docs/PROVENANCE.md` shows how the template credits its own). No real people's photos or voices without their OK, no other company's
logos or characters, nothing hateful or NSFW.
